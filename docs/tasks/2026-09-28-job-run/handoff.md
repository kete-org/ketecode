**Deviations / decisions not fully spelled out in the plan**
- **`job-run.ts`'s `Input`/`Deps` don't literally match the plan's informal list.** The plan's Design said `Deps: {client, git, readFile/stat/exists, dataDir, auditDir, now, sleep, stdout, stderr, onInterrupt, environment?}`. I added `realpath` (needed for the D1 directory-equality check), `randomId` (injectable id8 source), `attached` (whether `client` is the background service, gating `session.environment`), and `auditPollTimeoutMs?` (optional, defaults to 5000 in production; tests shrink it so the "no local audit file" fallback tests don't take a real 5s each — see job-run.test.ts's header comment). None of these change the plan's behavior, only testability.
- **`job-run.ts` never imports `job-spec.ts`/`job-git.ts`, even for types.** The plan's file-list note ("imports only @opencode/client/promise, @opencode/schema, @opencode/util, node:*, effect") reads literally as excluding sibling `cli/src/*` files entirely, not just heavy ones. I took it literally: `JobRun.Spec`/`JobRun.Git` are separate, structurally-identical interfaces declared in `job-run.ts` itself; `job.ts` passes `JobGit` and a `JobSpec.parse(...)` result into them, relying on structural typing. `job-run.ts`'s header explains this.
- **`tsgo -b` did *not* reject the cross-package import** (the plan's flagged risk, step 7). I verified directly: adding `packages/cli` to `packages/server/tsconfig.json`'s `references` fails (`packages/cli` isn't a composite project — inherited `noEmit: true`/no `composite: true`), but the plan's actual scenario — a **plain relative import**, `../../../cli/src/kete/job-run`, with **no** `references` entry — works fine under both `tsgo -b` and `bun test`, because TS project references only matter for the incremental build DAG, not for module resolution. So the e2e test lives at `packages/server/test/kete/job-run.test.ts` exactly as planned; the `packages/cli/test/kete/` fallback wasn't needed. (I reverted my probe edit to `packages/server/tsconfig.json` before writing the real test — `git diff` on that file is empty.)
- **D3 gap I found while writing the e2e test, not the plan:** a `permission.asked` for a **subagent** of the job's root session isn't recognized as the runtime-bug case — only the root session's own `sessionID` is matched in `watchEvents`. Tracking a job's whole session family from the event stream (without core) would need a way to learn child session ids as they're created, which nothing in the client API surfaces cheaply. Documented as a known gap in `docs/jobs.md` and the module's `watchEvents` doc comment, not fixed.
- **`session.create` now sets an explicit `title`** (`spec.prompt` truncated to 80 chars) — not in the plan's Design bullet list, but necessary: without it, upstream's auto-title-generation makes an extra, unscripted model request before the job's own first step, which is wasteful for an unattended run and also broke the e2e test's `TestLLM` response queue ordering (the title request silently ate the test's first scripted response). This is a genuine behavior improvement, not just a test workaround — jobs shouldn't pay for a title nobody reads via the CLI. Should get a one-line mention in `docs/context/modules/cli.md`'s Quick answers list.
- **Cleanup-before-start (Design) covers `session.create` and `session.environment` failures**, not "any failure before the prompt is submitted" as literally as the wording suggests — e.g. an event-subscribe failure before the prompt is admitted also triggers `cleanup()` (see the `catch` block's `!admitted` branch), but once the event stream connects successfully the worktree/branch are kept even if the prompt call itself then fails (a stuck server after a live connection is treated the same as "the prompt might already be running somewhere"). This matches the spirit but wasn't enumerated case-by-case in the plan.

## 2026-09-28 implementer (reviewer fixes)

Addressed the coordinator's three reviewer findings. No plan change — these are hardening fixes within the approved design.

1. **major, `job-spec.ts` `prompt_file` path traversal.** `prompt_file` had no containment check: a spec could name `../../.ssh/id_rsa` (or an absolute path, or a symlink inside the spec directory pointing outside it) and its contents would be sent to the model as the prompt. Fixed: after confirming the resolved path exists and is a regular file, both the spec directory and the resolved file are run through a new `Deps.realpath` (`fs.realpath`, resolves symlinks), then `path.relative(realSpecDir, realFile)` must not be `""`, start with `..`, or be absolute (the absolute case covers a Windows different-drive result too) — otherwise refused: `prompt_file: must be inside the job spec's directory`. Also shrank the size cap from 1 MiB to 256 KiB (reviewer's number). `job.ts`'s `specDeps` now passes the real `realpath`.
   - Files: `packages/cli/src/kete/job-spec.ts` (`Deps.realpath`, the containment check, `MAX_PROMPT_FILE_BYTES = 256 * 1024`), `packages/cli/src/kete/job.ts` (`specDeps.realpath`), `packages/cli/test/kete/job-spec.test.ts` (fake `deps` gained a `realpaths` override to simulate a symlink; new tests: `..` escape, an absolute path outside, a symlink inside the dir pointing outside, a nested file inside — allowed, an oversized file at the new 256 KiB threshold instead of 1 MiB).
2. **minor, `job-run.ts` `parseModel` could throw uncaught.** `validateSpec` (called first, before any git/client call) now also validates `spec.model` via `Model.Ref.parse`, refusing with `spec.model: ...` — so a bad model from a hand-built `Spec` (bypassing `job-spec.ts`) is caught at the very top, matching AC1's "zero client/git calls" property. The `parseModel(spec.model)` call site itself (after the worktree may already exist) is also wrapped in try/catch as defense in depth: on a throw it runs `cleanup()` and returns a `refused` outcome instead of an uncaught rejection.
   - Files: `packages/cli/src/kete/job-run.ts` (`validateSpec`'s new model check; the `parseModel` call site wrapped), `packages/cli/test/kete/job-run.test.ts` (new case: "an invalid model reference: zero client and git calls").
3. **docs.** `docs/jobs.md`'s `prompt_file` row now states the containment rule and the 256 KiB cap.
